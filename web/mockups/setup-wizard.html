Stock footage

One of these two keys is required. Moving footage can only come from Pexels or Pixabay — those are the only two sources AVF has, and each needs its own free API key. Paste at least one to continue.

There is no keyless substitute, so this step cannot be skipped. AVF has no AI video generator; without a stock key the scenes become still pictures with a slow zoom across them, which is not a video worth watching. The free still service that would supply those pictures is also unreliable at video resolution — in testing it failed 2 of 5 requests, quietly returned 576×1024 when asked for 1080×1920, took 22–47 seconds each time, and stamped its own watermark in the corner, which the final crop does not remove.

Pexels
Where do I get a Pexels key? — free, about a minute
  1. Open pexels.com/api and click Get Started.
  2. Sign up or log in. A free Pexels account is enough — no credit card, no company details, and this is a normal Pexels account, not a separate developer signup.
  3. You land on a form asking for an application name and description. It is only ever shown to you — put anything, e.g. name AVF, description local video generator.
  4. Submit. Your key is displayed immediately on that page: a long string of letters and numbers. Copy it and paste it in the box below.

The free tier is meant for exactly this kind of use. AVF caches every search on disk for 24 hours, so a video costs a handful of requests, not one per scene.

Pixabay
Where do I get a Pixabay key? — free, about a minute
  1. Create a free account at pixabay.com if you do not have one, then log in.
  2. Open pixabay.com/api/docs while logged in. This page is the key page — there is no separate application form to fill in.
  3. Near the top of that page, in the parameter table, find the row for key. Your personal API key is shown right there, in place of the placeholder. Copy it and paste it in the box below.

If you see a placeholder instead of a real key, you are not logged in — log in and reload the page. Pixabay allows 100 requests per minute; AVF deliberately stays at 30 and caches every search for 24 hours, which is what their API terms require.

Turn both on and AVF searches both and takes the better match. A box that is ticked with no key pasted is ignored — that is why each box sits next to its own key field.

Before you connect: set the OAuth consent screen to “In production”.
Left on “Testing”, Google expires the refresh token after 7 days — day 1 works, day 8 uploads start failing with an auth error and it looks like an AVF bug. Publishing to production is free and needs no Google verification review; you just click through a “Google hasn’t verified this app” screen once.
How do I get client_secret.json? — six steps, free, no coding
  1. Create a project. Open console.cloud.google.com/projectcreate. Give it any name (avf is fine), leave “Location” as No organisation, and click Create. Wait for the notification that says it is ready, then make sure this project is the one selected in the project picker at the very top of the page — every step below applies to whichever project is selected there, and picking the wrong one is the most common way to end up with a file AVF cannot use.
  2. Turn on the YouTube API. Open YouTube Data API v3. Check the picker still shows your project, then click the blue Enable button. If you instead see Manage, it is already enabled — continue.
  3. Fill in the consent screen. Open the consent screen. In newer consoles this page is titled Google Auth Platform and is split into tabs on the left; in older ones it is one long form. Either way:
    • User type: External (this means “any Google account”, not “outside my company”).
    • App name: anything — AVF. You are the only person who will ever see it.
    • User support email and developer contact email: your own address, twice.
    • Audience / Publishing status: leave Testing for now — the next step fixes it. If it asks for test users, add your own Gmail address.
    • Scopes: click Add or remove scopes and paste https://www.googleapis.com/auth/youtube.upload into the filter box, tick it, then Update. Optionally also add https://www.googleapis.com/auth/youtube.readonly if you want the analytics page to show real numbers.
  4. ⚠️ Publish the app — do not leave it in “Testing”. On that same consent screen, find Publish app (in the new console it is under the Audience tab) and confirm. The status must read In production. This is the single step everyone misses; see the amber box above for what it costs. Publishing is free, needs no Google review, and the only visible effect is that you click through a “Google hasn’t verified this app” screen once — choose Advanced → Go to AVF (unsafe). That wording is Google’s default for any app that has not paid for verification; it is not a warning about AVF specifically.
  5. Create the credential. Open Credentials → + Create credentials → OAuth client ID. Application type must be Desktop app. Name it anything and click Create.
    Choose Desktop app, not “Web application”. The two produce different JSON files: a Web-application file has a "web" section, a Desktop-app file has an "installed" section, and AVF only accepts the latter. Picking the wrong one is the other way to get a file that is rejected here.
  6. Download it. A dialog appears with your client ID and secret — click Download JSON. Your browser saves a file named something like client_secret_1234-abc.apps.googleusercontent.com.json. Leave the name exactly as it is — despite the name in older instructions, AVF reads the file’s contents and never looks at the filename, so renaming it to client_secret.json is unnecessary. If you have lost the dialog, the same download link is always available under Credentials in the ⬇ icon next to your OAuth client.

That is all of it. Nothing here costs money and there is no approval queue — the whole sequence takes about five minutes. The file you just downloaded is a credential for your own project, not an account or a subscription, and it is safe to keep on this machine.

You’re set up

Three things worth knowing before the first render.

  • Voice and subtitle models (~340 MB) download the first time you produce a video. That first run is slow; later ones aren’t.
  • Scenes are filled from stock footage, so a scene is real moving video. If a search finds nothing for a scene, AVF falls back to a still image for that one scene only. Adding a second key — the other of Pexels or Pixabay — is the easiest way to reduce that. Keys live in Settings → Media.
  • Everything AVF writes lives in one folder — ~/Library/Application Support/AVF on macOS, %APPDATA%\AVF on Windows. Rendered videos are under content/rendered/, logs under runtime/logs/. It is read-only here: there is no output-folder setting to change.

Behaviour notes. The gate lives in web/app/layout.tsx: on mount, if the path is not /setup and GET /api/settings/llm reports has_api_key: false, redirect to /setup. It only ever fires on step 1 — once a key exists the wizard never appears again, and it stays reachable by URL. The dashboard’s empty state gets a “Finish setup” link too, for anyone who skipped past it.

Stock footage is required, not optional. The first two drafts treated it as skippable and offered “use free AI stills” as the alternative. That was wrong, and the evidence is in the code, not a matter of taste. providers/stock.py:37 defines exactly two sources, PROVIDERS = ("pexels", "pixabay"), and stock_sources() filters them to the ones that have a key — so no key means no stock at all, with no third source and no keyless fallback. providers/video/__init__.py is empty (0 bytes), and AnimateDiff appears nowhere in the repo, so there is no AI video generator to fall back on either. The only keyless path is image.provider → pollinations → a generated still with Ken Burns zoom/pan (editor.py:36-41), which is a picture, not footage.

Measured, not assumed. Five requests to Pollinations at production resolution (1080×1920), through the app’s own ImageProvider.generate(): two returned HTTP 500, and the three that succeeded came back as 576×1024 — half the requested size, which _fit() then upscales 1.88×. Each successful image took 22–47 seconds. Both of the ones viewed carry a pollinations.ai watermark in the bottom-right that nologo=true did not remove, and because the source is already 9:16 the centre crop is a no-op, so the watermark reaches the finished video. There is no retry around the call (generate() tries each tier once), so a single 500 drops that scene straight to _gen_gradient — a flat two-tone colour with no content at all. Hence the removed skip button, and hence the disabled state on Save and continue until a key field is filled.

Still needs a server-side guard. The wizard gate is client-side only, so POST /api/produce should also refuse with 409 when no stock key is stored. That guard does not exist yet — the LLM one does, and is the shape to copy: server.py:452-456 already raises 409 with “AI model not configured — open /setup”, so Fase 0.3 shipped that half. Nothing equivalent covers stock, and POST /api/settings/image only validates at save time (server.py:1248). The stale progress message at pipeline.py:219 — “Scene asset N/M (AI clip can take ~11 min)” — should go too: it is left over from the AnimateDiff era and promises an AI video that no longer exists anywhere in the code.
